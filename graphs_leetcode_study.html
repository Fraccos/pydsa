Graphs: From Fundamentals to Medium & Hard

A practical, NeetCode-inspired study guide for SDE mid-level interviews. Learn how graphs are represented, when BFS or DFS applies, and build toward the recurring patterns behind graph problems.

Includes embedded diagrams, Python examples, complexity analysis, a study roadmap, and your first practice problem. This file is self-contained and works offline. Companion guide: Binary Trees.

1. What is a graph?

A graph is a set of nodes (vertices) connected by edges. Unlike a tree, a graph has no designated root and may contain cycles — a tree is just a special kind of graph: connected and acyclic.

  • Undirected vs. directed: an undirected edge works both ways; a directed edge (drawn with an arrow) has a direction, e.g. course prerequisites.
  • Neighbor / adjacency: nodes directly connected by an edge.
  • Degree: the number of edges touching a node (for directed graphs, split into in-degree and out-degree).
  • Path: a sequence of nodes connected by edges. A shortest path has the fewest edges (or lowest total weight).
  • Cycle: a path that starts and ends at the same node.
  • Connected component: a maximal group of nodes where every pair is reachable from the other.
  • Weighted graph: each edge carries a cost, such as distance or time.

2. Representing a graph in Python

LeetCode usually passes an edge list, a grid, or a node object. You convert it to an adjacency list — a dictionary mapping each node to its neighbors. This is the workhorse representation.

from collections import defaultdict

edges = [[0, 1], [0, 3], [0, 4], [1, 2], [1, 4], [2, 4]]

def build_graph(edges, n):
    graph = defaultdict(list)
    for u, v in edges:
        graph[u].append(v)
        graph[v].append(u)   # remove for a directed graph
    return graph

For a weighted graph, store pairs:

graph[u].append((v, weight))

3. Graph vs. tree vs. other structures

Tree

Connected, acyclic, n − 1 edges, one path between any two nodes. Recursion on subtrees works because there are no cycles.

Useful for: hierarchies, ordered data (BST), expression parsing.

Graph

Arbitrary connections, may be cyclic and disconnected. Requires a visited set to avoid infinite loops.

Useful for: networks, dependencies, reachability, shortest paths.

Grid as graph

A 2D matrix where each cell is a node adjacent to its up/down/left/right neighbors. No explicit edges needed.

Useful for: islands, flooding, rotting spread, maze problems.

The single biggest practical difference from trees: graphs can revisit nodes, so every traversal needs a visited set (or marking cells in place). Forgetting it is the most common source of infinite loops.

4. When should you use BFS vs. DFS?

Both visit every reachable node in O(V + E). The choice depends on what the question asks for.

Signal in the promptChooseWhy
"Shortest path", "minimum steps", "nearest node" (unweighted)BFSBFS explores in rings of increasing distance, so the first time you reach a node is via a shortest path
"Level by level", spread over time (rotting oranges)BFSA deque processes nodes in distance order, one "layer" per step
"Can you reach…", "count islands/components", "all paths"DFSReachability doesn't care about distance; DFS is shorter to write, recursively
"Order tasks by dependencies", "prerequisites"Topological sortDirected acyclic graphs define a valid processing order
"Connected if…", union/merge groups dynamicallyUnion-FindIncremental grouping without rebuilding the graph
"Shortest path with weights"DijkstraBFS alone is wrong when edges have different costs

5. Four core interview patterns

Pattern 1 — BFS (level-by-level with a queue)

The template is the same one from tree level-order traversal, plus a visited set. Track distance by processing one level at a time or by storing (node, dist) pairs.

from collections import deque

def bfs(graph, start):
    visited = {start}
    queue = deque([(start, 0)])

    while queue:
        node, dist = queue.popleft()
        # process node at distance `dist`
        for nei in graph[node]:
            if nei not in visited:
                visited.add(nei)
                queue.append((nei, dist + 1))

Time: O(V + E). Space: O(V). Mark nodes visited when enqueuing, not when dequeuing, or the queue can blow up with duplicates. Common problems: Shortest Path in Binary Matrix (1091), Rotting Oranges (994), Word Ladder (127), Clone Graph (133).

Pattern 2 — DFS (and counting components)

Recursion works exactly as in trees; the only addition is a visited set checked before recursing. Counting connected components = count how many DFS sweeps you launch.

def dfs(node, graph, visited):
    visited.add(node)
    for nei in graph[node]:
        if nei not in visited:
            dfs(nei, graph, visited)

def count_components(n, edges):
    graph = build_graph(edges, n)
    visited = set()
    count = 0
    for node in range(n):
        if node not in visited:
            dfs(node, graph, visited)
            count += 1
    return count

Time: O(V + E). Space: O(V) plus recursion depth — Python's default recursion limit (~1000) matters, so for large graphs convert to an explicit stack. Common problems: Number of Islands (200), Number of Provinces (547), All Paths from Source to Target (797).

Pattern 3 — Grids as graphs

A cell (r, c) is a node; its neighbors are the four directions. A small directions list keeps code clean:

directions = [(1, 0), (-1, 0), (0, 1), (0, -1)]

def neighbors(r, c, rows, cols):
    for dr, dc in directions:
        nr, nc = r + dr, c + dc
        if 0 <= nr < rows and 0 <= nc < cols:
            yield nr, nc

Instead of a visited set, you often mutate the grid in place (e.g. sink visited land by setting it to "0"). This is the same BFS/DFS machinery — grids just hide the graph. Common problems: Number of Islands (200), Max Area of Island (695), Pacific Atlantic Water Flow (417), Surrounded Regions (130).

Pattern 4 — Topological sort (directed, acyclic)

When a problem is about dependencies — courses, build order, tasks — model it as a directed graph and produce an order where every node comes after its prerequisites. Kahn's algorithm (BFS with in-degrees) is the interview-friendly version:

from collections import deque

def topo_sort(num_nodes, edges):
    graph = defaultdict(list)
    indegree = [0] * num_nodes
    for u, v in edges:          # u depends on v, or vice versa — read carefully!
        graph[v].append(u)
        indegree[u] += 1

    queue = deque(i for i in range(num_nodes) if indegree[i] == 0)
    order = []

    while queue:
        node = queue.popleft()
        order.append(node)
        for nei in graph[node]:
            indegree[nei] -= 1
            if indegree[nei] == 0:
                queue.append(nei)

    return order if len(order) == num_nodes else []  # [] means a cycle
Edge direction is the #1 trap. For "[a, b] means b must come before a", add the edge from b to a and increment a's in-degree. Getting it backwards silently fails on cycle detection.

Time: O(V + E). If the order has fewer than num_nodes nodes, a cycle exists — that's how you detect impossibility. Common problems: Course Schedule (207), Course Schedule II (210), Alien Dictionary (269).

6. Two tools to recognize (not master yet)

Union-Find (Disjoint Set Union)

When edges arrive incrementally and the question is "are these connected?" or "how many groups?", Union-Find merges sets in near-constant amortized time. Know that it exists and what it looks like:

class UnionFind:
    def __init__(self, n):
        self.parent = list(range(n))
        self.rank = [0] * n
        self.count = n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]  # path compression
            x = self.parent[x]
        return x

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False
        if self.rank[ra] < self.rank[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        if self.rank[ra] == self.rank[rb]:
            self.rank[ra] += 1
        self.count -= 1
        return True

Common problems: Number of Connected Components (323), Redundant Connection (684), Accounts Merge (721).

Dijkstra (weighted shortest path)

Dijkstra is BFS with a min-heap instead of a queue: always expand the cheapest known node next. Uses heapq — see the companion guide Heaps & Priority Queues.

import heapq

def dijkstra(graph, start):
    dist = {start: 0}
    heap = [(0, start)]

    while heap:
        d, node = heapq.heappop(heap)
        if d > dist[node]:          # stale entry, skip
            continue
        for nei, w in graph[node]:
            nd = d + w
            if nd < dist.get(nei, float('inf')):
                dist[nei] = nd
                heapq.heappush(heap, (nd, nei))
    return dist

Time: O((V + E) log V). Non-negative weights only. Common problems: Network Delay Time (743), Cheapest Flights Within K Stops (787, which needs a variant), Path with Minimum Effort (1631).

8. Interview checklist

  1. Direction: Is the graph directed or undirected? Which way does each input edge point?
  2. Representation: Edge list, grid, or node objects? Build the adjacency list up front.
  3. Visited: Where is my visited set (or in-place marking)? Can a node be enqueued twice?
  4. Disconnection: Can nodes be unreachable? Do I need to loop over all nodes, or start from one?
  5. Distances: Unweighted → BFS. Weighted, non-negative → Dijkstra. Anything else is a red flag.
  6. Cycles: For directed graphs, is detecting a cycle part of the answer (course schedule)?
  7. Recursion depth: Is n large enough that DFS recursion could hit Python's limit?
  8. Edge cases: Empty graph, single node, self-loops, duplicate edges, disconnected input.

9. First practice problem — LeetCode 200

Number of Islands

Given an m x n grid of '1's (land) and '0's (water), return the number of islands. An island is a group of land cells connected horizontally or vertically.

Every land cell belongs to exactly one island. So: scan the grid; each time you find an unvisited land cell, that's a new island — flood-fill (DFS or BFS) from it, marking everything reachable.

Recurrence: islands(grid) = number of times a fresh '1' is found during the scan. Each flood-fill marks one whole island so it is never counted twice.

class Solution:
    def numIslands(self, grid: list[list[str]]) -> int:
        if not grid:
            return 0

        rows, cols = len(grid), len(grid[0])

        def sink(r, c):
            if r < 0 or r >= rows or c < 0 or c >= cols:
                return
            if grid[r][c] != '1':
                return
            grid[r][c] = '0'   # mark visited in place
            sink(r + 1, c)
            sink(r - 1, c)
            sink(r, c + 1)
            sink(r, c - 1)

        count = 0
        for r in range(rows):
            for c in range(cols):
                if grid[r][c] == '1':
                    sink(r, c)
                    count += 1
        return count

Time: O(rows · cols) — each cell is visited at most a constant number of times. Space: O(rows · cols) worst case for the recursion stack (a grid that is all land). For very large grids, replace the recursion with an explicit stack or a BFS deque.
