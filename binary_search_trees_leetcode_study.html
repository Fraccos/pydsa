1. What is a BST?

A Binary Search Tree is a binary tree with an ordering rule. For every node:

  • all values in its left subtree are less than the node's value, and
  • all values in its right subtree are greater than the node's value.
The classic mistake: the rule applies to the entire subtrees, not just the immediate children. A node with value 12 placed in the left subtree of the root 8 above would violate the BST even if every parent-child pair looked locally ordered. Validation must carry bounds down the tree (Section 5).

The conventional assumption is no duplicate values. If duplicates can appear, a common convention is left subtree <= node, but LeetCode problems usually state what to do — ask if unclear.

2. Representing a BST in Python

Exactly the same TreeNode as any binary tree — the BST is a property of the values, not the class:

class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

What changes is how you navigate. Instead of exploring both children, a search only descends one side:

def search(root, target):
    node = root
    while node:
        if target < node.val:
            node = node.left      # everything here is smaller
        elif target > node.val:
            node = node.right     # everything here is larger
        else:
            return node           # found it
    return None

Time: O(h) — O(log n) if balanced, O(n) if skewed. Each comparison eliminates an entire subtree, like binary search on a sorted array.

3. BST vs. binary tree vs. hash map

Binary tree

No ordering. Search visits potentially every node: O(n).

Useful for: hierarchies and recursive decomposition where order doesn't matter.

BST

Global ordering gives O(h) search, insert, delete, plus sorted-order iteration and range queries for free.

Useful for: ordered data, kth-element, floor/ceiling, predecessor/successor.

Hash map

O(1) average point lookups, but values come out unordered — no kth-smallest, no ranges, no successor.

Useful for: membership and counting where order is irrelevant.

The interview framing: a hash map answers "is this exact key present?" instantly. A BST additionally answers "what's the smallest key ≥ x?", "how many keys below x?", "give me the keys in order" — questions that would require scanning the whole hash map.

The caveat interviewers expect you to state: all BST guarantees are O(h), and h is only O(log n) when the tree is balanced. A tree built from sorted input degrades to a linked list. Self-balancing trees (AVL, red-black) fix this — Python's sortedcontainers.SortedList embodies the idea, though it isn't in the standard library.

4. When should you use a BST?

Reach for BST thinking whenever a problem combines hierarchy with order:

Signal in the promptBST insight to apply
"Kth smallest/largest element"Inorder traversal yields sorted order; stop at the kth visit
"Validate / it's a BST"Propagate (low, high) bounds, or check inorder is strictly increasing
"LCA of two nodes in a BST"The LCA is the first node where p and q split to different sides — O(h), no parent pointers
"Range sum / count values in [L, R]"Prune: skip entire subtrees outside the range
"Insert / delete / successor / predecessor"Descend one side at a time; deletion needs the successor trick (Section 6)
"Build a BST from data"Sorted array's middle element becomes a balanced root (108)

Conversely, if the tree is not a BST, none of these apply — you're back to general tree DFS/BFS from the Binary Trees guide, typically O(n).

5. Four core interview patterns

Pattern 1 — Inorder traversal is your superpower

Inorder (left → root → right) visits a BST's values in strictly increasing order. This single fact unlocks a family of problems:

def inorder(root):
    if root is None:
        return
    yield from inorder(root.left)
    yield root.val
    yield from inorder(root.right)

For kth-smallest, you don't even need the whole traversal — count visits and stop early. For "find the inorder successor of value x", inorder gives the next value after x. If a general binary tree problem involves "sorted output" or "closest value to k", and the input is a BST, this is the lever.

Pattern 2 — Validate with bounds

The trap from Section 1 deserves its pattern. Each recursive call passes down the valid open interval for its subtree:

def is_valid(node, low=float('-inf'), high=float('inf')):
    if node is None:
        return True
    if not (low < node.val < high):
        return False
    return (is_valid(node.left, low, node.val) and
            is_valid(node.right, node.val, high))

A neat alternative: run an inorder traversal and assert each value is strictly greater than the previous one. Both are O(n). Common problems: Validate BST (98), Recover BST (99) — where exactly one inorder swap broke the order.

Pattern 3 — Descend, don't traverse: LCA and range queries

When searching for a single node or answer, you can often go straight down one path instead of visiting everything. For the lowest common ancestor of two values p and q:

def lowest_common_ancestor(root, p, q):
    node = root
    while node:
        if p.val < node.val and q.val < node.val:
            node = node.left       # both in left subtree
        elif p.val > node.val and q.val > node.val:
            node = node.right      # both in right subtree
        else:
            return node            # they split here — this is the LCA

Range queries prune the same way: recurse into the left child only if L < node.val, into the right only if node.val < R. Common problems: LCA of a BST (235), Range Sum of BST (938), Closest Value in BST (270).

Pattern 4 — Structural surgery: insert, delete, build

Insertion is a search that ends in a None: walk down exactly the path you would walk to find the value, and when you fall off the tree, hang the new node there. The new node is always a leaf, and no rebalancing is expected in interviews.

def insert(root, val):
    if root is None:
        return TreeNode(val)          # fell off the tree — attach here
    if val < root.val:
        root.left = insert(root.left, val)
    elif val > root.val:
        root.right = insert(root.right, val)
    return root

The root.left = insert(...) assignment is the idiom that confuses people: it re-links each node to its (unchanged) subtree on the way back up, and actually does work only at the None — where it attaches the new leaf. The iterative version makes the mechanics explicit:

def insert_iterative(root, val):
    if root is None:
        return TreeNode(val)
    node = root
    while True:
        if val < node.val:
            if node.left is None:
                node.left = TreeNode(val)
                return root
            node = node.left
        elif val > node.val:
            if node.right is None:
                node.right = TreeNode(val)
                return root
            node = node.right
        else:
            return root              # duplicate — convention-dependent, usually ignored

Cost: one root-to-attach-point path — O(h) time (O(log n) balanced, O(n) skewed), O(1) extra space iteratively or O(h) recursion stack. A useful contrast with the heap: a heap push always travels leaf-to-root (its position is forced by completeness), while a BST insert can land at any depth — its cost is determined by the value, which is exactly why repeatedly inserting sorted data into a BST builds a skew (a linked list) rather than a balanced tree.

Delete (450) has three cases, and the third is the famous one:

  • Leaf or one child: replace the node with its child (or None).
  • Two children: find the node's inorder successor (smallest value in the right subtree — go right once, then all the way left), copy its value into the node, then delete that successor, which has at most one child.
def delete_node(root, key):
    if root is None:
        return None
    if key < root.val:
        root.left = delete_node(root.left, key)
    elif key > root.val:
        root.right = delete_node(root.right, key)
    else:
        if root.left is None:
            return root.right
        if root.right is None:
            return root.left
        successor = root.right
        while successor.left:
            successor = successor.left
        root.val = successor.val
        root.right = delete_node(root.right, successor.val)
    return root

Building: to turn a sorted array into a balanced BST, the middle element is the root and the two halves recurse (108). All of these are O(h) per operation, O(n) to build.

7. Interview checklist

  1. Is it actually a BST? If the problem says so, use O(h) tools — never do a generic O(n) traversal when a descent suffices.
  2. Subtree-wide vs. local: Does my reasoning hold for entire subtrees, or only immediate children?
  3. Bounds: For validation, what interval does each recursive call inherit?
  4. Duplicates: Are they possible, and does the problem define a convention?
  5. Balance: Am I quoting O(log n) without justification? Say "O(h), O(log n) if balanced".
  6. Traversal choice: Do I need sorted order (inorder), or just a path down the tree?
  7. Early stopping: Can I stop the inorder at the kth visit instead of building a full list?
  8. Edge cases: Empty tree, single node, target equal to a node, skewed tree, deleting the root.

8. First practice problem — LeetCode 230

Kth Smallest Element in a BST

Given the root of a BST and an integer k, return the kth smallest value among all nodes (1-indexed).

Inorder traversal emits values smallest-first. The kth value emitted is the answer. Naively you could build the whole sorted list; the polished solution stops as soon as the counter hits k.

Pattern: inorder traversal + a counter. visit(node) = recurse left, consume node, recurse right — and "consume" means increment the counter and return the value if it equals k.

class Solution:
    def kthSmallest(self, root: Optional[TreeNode], k: int) -> int:
        self.count = 0
        self.result = None

        def inorder(node):
            if node is None or self.result is not None:
                return
            inorder(node.left)
            self.count += 1
            if self.count == k:
                self.result = node.val
                return
            inorder(node.right)

        inorder(root)
        return self.result

Time: O(H + k) — you descend to the smallest node (height H) and then visit k nodes; in the worst case O(n). Space: O(H) for the recursion stack.

Follow-up the interviewer will ask: what if the tree is frequently inserted into and deleted from? Then an inorder list goes stale — the real answer is augmenting each node with the size of its subtree, so you can descend to the kth element in O(h) without traversal.

Practice prompts

  1. Why does inorder traversal of a BST produce sorted values — can you argue it from the invariant?
  2. What should happen once the counter reaches k — why is the early-exit check before and after recursion useful?
  3. How would you find the kth largest instead — what's the minimal change?
