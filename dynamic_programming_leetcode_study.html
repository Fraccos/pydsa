1. What is dynamic programming?

Dynamic programming (DP) is a technique for problems whose answers decompose into overlapping subproblems: the same smaller subproblem shows up many times, and each subproblem's answer only depends on answers to even smaller ones. DP solves each distinct subproblem once, stores the result, and reuses it.

The classic demonstration is Fibonacci. Naive recursion recomputes the same values exponentially many times:

  • Overlapping subproblems: the same states recur — that's what makes caching worthwhile.
  • Optimal substructure: the answer for a state is built from answers of smaller states — ways(n) from ways(n−1) and ways(n−2).
  • State: the minimal description of a subproblem — "max loot from the first i houses", "ways to make amount a with coins so far". Choosing the state is the real design work.
  • Recurrence: the rule connecting a state to smaller states, plus base cases.
The whole game is three questions: (1) What is a state? (2) What is the recurrence from smaller states? (3) What are the base cases? Everything else — memoization, tables, loops, space tricks — is bookkeeping.

2. Representing DP in Python

Two equivalent styles. Top-down (memoization) keeps the natural recursive formulation and caches results in a dict or array:

from functools import lru_cache

def fib(n):
    memo = {}

    def helper(k):
        if k <= 1:
            return k
        if k in memo:
            return memo[k]
        memo[k] = helper(k - 1) + helper(k - 2)
        return memo[k]

    return helper(n)

# or, for one-argument functions, in one line:
@lru_cache(maxsize=None)
def fib_cached(n):
    return n if n <= 1 else fib_cached(n - 1) + fib_cached(n - 2)

Bottom-up (tabulation) fills a table from the base cases upward, in dependency order:

def fib(n):
    if n <= 1:
        return n
    dp = [0] * (n + 1)
    dp[1] = 1
    for i in range(2, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]
    return dp[n]

Both have identical time complexity. In interviews, write whichever comes out first (usually top-down), state the recurrence aloud, then offer the bottom-up conversion — often with the space optimization, e.g. two variables instead of a full array for Fibonacci-style recurrences.

3. DP vs. recursion vs. greedy vs. BFS

Plain recursion

Same recurrence, no cache. Correct but exponential when subproblems overlap heavily.

Useful for: a first correct draft — then add the memo and watch the complexity collapse.

Greedy

Takes the locally best move and never revisits. O(n log n) or better, but only correct when a local choice can't hurt the global optimum.

Useful for: interval scheduling, jump game — but proving greedy-safety is hard. When you can't prove it, DP is the fallback.

BFS

Explores states outward from a start. For unweighted state graphs, the first time you reach a state is optimal — that's DP on an implicit graph where every edge has equal weight.

Useful for: shortest path in mazes, word ladders. See the Graphs guide.

A helpful reframe: DP is shortest-path/longest-path on a DAG of states. Each table cell is a node; edges point from a state to the states it depends on. Topological order of that DAG = your loop order. This is why DP works on problems like "minimum edit distance" but BFS is wrong for weighted or max-min objectives.

The anti-signs: if a locally best choice provably can't hurt (greedy), or the structure is an unweighted graph search (BFS), or there's no overlap between subproblems (plain divide & conquer like merge sort), DP is the wrong tool. Overlapping subproblems are the entry fee.

5. Four core interview patterns

Pattern 1 — Linear 1-D DP (decisions along a sequence)

State: dp[i] = answer for the first i items. The recurrence often has a small "decision": at each step, take or skip.

def rob(nums):                # LeetCode 198: House Robber
    take, skip = 0, 0         # max loot if we take / skip the previous house
    for num in nums:
        take, skip = skip + num, max(take, skip)
    return max(take, skip)

dp[i] = max(dp[i−1], dp[i−2] + nums[i]) — rob this house (so the previous must be skipped) or don't. Two variables instead of an array, since the recurrence only looks back two steps: O(n) time, O(1) space. Common problems: Climbing Stairs (70), House Robber (198), House Robber II (213, circular version), Min Cost Climbing Stairs (746).

Pattern 2 — Grid 2-D DP

State: dp[r][c] = answer for the sub-grid ending at cell (r, c). Fill row by row; each cell depends on its top and left neighbors.

def unique_paths(m, n):       # LeetCode 62
    dp = [[1] * n for _ in range(m)]   # first row and column: exactly 1 way
    for r in range(1, m):
        for c in range(1, n):
            dp[r][c] = dp[r - 1][c] + dp[r][c - 1]
    return dp[m - 1][n - 1]

Time: O(m·n) — proportional to the number of states, the universal DP cost rule. Common problems: Unique Paths (62), Minimum Path Sum (64), Maximal Square (221), Dungeon Game (174).

Pattern 3 — Knapsack: coin change and subset sums

State: dp[a] = the answer for capacity/amount a. Two flavors matter because the loop order changes:

def coin_change(coins, amount):    # LeetCode 322 — unbounded: reuse coins
    dp = [float('inf')] * (amount + 1)
    dp[0] = 0
    for a in range(1, amount + 1):
        for coin in coins:
            if coin <= a:
                dp[a] = min(dp[a], dp[a - coin] + 1)
    return dp[amount] if dp[amount] != float('inf') else -1

def can_partition(nums):           # LeetCode 416 — 0/1: each coin used once
    total = sum(nums)
    if total % 2:
        return False
    dp = [False] * (total // 2 + 1)
    dp[0] = True
    for num in nums:
        for a in range(total // 2, num - 1, -1):   # backwards = use once
            dp[a] = dp[a] or dp[a - num]
    return dp[total // 2]
The loop-order rule: unbounded knapsack iterates amounts forward (a coin may build on itself); 0/1 knapsack iterates backwards (so each item is used at most once). Interviewers specifically probe this distinction.

Common problems: Coin Change (322), Partition Equal Subset Sum (416), Target Sum (494), Longest Common Subsequence's knapsack cousin — Combination Sum IV (377).

Pattern 4 — Two-sequence (string) DP

State: dp[i][j] = the answer for the first i characters of one string and the first j of another. The recurrence branches on whether the current characters match.

def longest_common_subsequence(a, b):    # LeetCode 1143
    m, n = len(a), len(b)
    dp = [[0] * (n + 1) for _ in range(m + 1)]
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if a[i - 1] == b[j - 1]:
                dp[i][j] = dp[i - 1][j - 1] + 1     # chars match — extend
            else:
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])  # drop one
    return dp[m][n]

The (m+1) × (n+1) table with an empty-prefix base row/column is a template worth memorizing — edit distance (72) is the same skeleton with min of three neighbors instead of max of two. Time: O(m·n), space: O(m·n), reducible to two rows. Common problems: LCS (1143), Edit Distance (72), Distinct Subsequences (115), Longest Increasing Subsequence (300 — 1-D cousin, O(n²) DP or O(n log n) with binary search).

7. Interview checklist

  1. State: Can I describe a subproblem in one sentence with indices? ("the answer using the first i items and budget a")
  2. Recurrence: Does the state depend only on smaller states? No cycles?
  3. Base cases: What are the values for empty prefixes, zero capacity, the first row/column?
  4. Direction of iteration: Am I filling in an order where dependencies are ready first? (Knapsack loop order!)
  5. What the answer is: Is the final answer dp[n], dp[m][n], or max(dp) over all states?
  6. Complexity: O(number of states × work per state) — can I state both factors?
  7. Space optimization: Does the recurrence only look back one row or k entries? Say so unprompted.
  8. Edge cases: Empty input, single element, impossible targets (−1 or False), zeros and negatives in the input.

8. First practice problem — LeetCode 70

Climbing Stairs

You are climbing a staircase with n steps. Each time you can climb either 1 or 2 steps. In how many distinct ways can you reach the top?

To land on step n, your last move was a single step from n−1 or a double step from n−2 — two disjoint cases that cover everything:

Recurrence: ways(n) = ways(n−1) + ways(n−2)
Base cases: ways(0) = 1 (one way: do nothing) and ways(1) = 1. This is Fibonacci in disguise — the point of the problem is to show you that recognizing the recurrence is the solution.

class Solution:
    def climbStairs(self, n: int) -> int:
        if n <= 1:
            return 1
        one, two = 1, 1        # ways(i-1), ways(i-2)
        for _ in range(2, n + 1):
            one, two = one + two, one
        return one

Time: O(n). Space: O(1) — the recurrence only looks back two steps, so two variables replace the whole array. The naive recursive version is O(2^n); add a memo and it drops to O(n); flatten the memo into the loop and the array drops to O(1). Walking through those three stages aloud is exactly what the interviewer wants to hear.

Practice prompts

  1. Why are the "last move was 1 step" and "last move was 2 steps" cases disjoint and exhaustive?
  2. What goes wrong if you solve this with plain recursion — what's the complexity and why?
  3. How would you change the recurrence if some steps are "broken" and cannot be landed on (LeetCode 746 is a cousin of this)?

Try writing the solution from memory, then explain the state, recurrence, base cases, and complexity aloud as you would in an interview.
