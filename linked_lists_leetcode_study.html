Linked Lists: From Fundamentals to LRU Cache

A practical, NeetCode-inspired study guide for SDE mid-level interviews. Singly and doubly linked lists, the pointer-surgery patterns, and the design problems — up to and including LRU Cache.

Includes embedded diagrams, Python examples, complexity analysis, a study roadmap with direct LeetCode links, and your first practice problem. This file is self-contained and works offline.

1. What is a linked list?

A linked list is a sequence of nodes, where each node stores a value and a reference (next) to the following node. Unlike an array, nodes are not contiguous in memory — the links are the order.

  • Head / tail: the first and last nodes. The tail's next is None.
  • Singly linked: each node points only forward. You can never go back.
  • Doubly linked: each node also stores prev, so you can walk both directions and delete a node in O(1) given the node itself.
  • Circular: the tail points back to the head (or anywhere — that's a cycle, the bug most cycle problems are about).
  • Sentinel / dummy node: a fake node placed before the head so that "the node before the one I'm deleting" always exists — even when that node is the head. The single most useful trick in this topic.

2. Representing a linked list in Python

class ListNode:

Build and walk a list manually:

head = ListNode(4, ListNode(8, ListNode(15)))

node = head
while node:
    print(node.val)      # 4, 8, 15
    node = node.next

Doubly linked lists are rarely handed to you by LeetCode — you build them yourself in design problems. The canonical example is LRU Cache (146): a hash map from key → node, plus a doubly linked list in recency order, so both lookup and reordering are O(1). Python's collections.OrderedDict implements exactly this machinery (its move_to_end is the built-in version of the pointer surgery below) — mention it, but implement the manual version if asked.

3. Linked list vs. dynamic array vs. deque

Python's list is a dynamic array, not a linked list. Know the trade-offs precisely — this is a common interview question:

5. Four core interview patterns

Pattern 1 — The dummy (sentinel) node

Whenever the head itself might be removed or replaced, prepend a dummy node and return dummy.next at the end. It deletes a whole category of if head is None special cases:

def merge_two_lists(l1, l2):        # LeetCode 21
    dummy = tail = ListNode()
    while l1 and l2:
        if l1.val <= l2.val:
            tail.next, l1 = l1, l1.next
        else:
            tail.next, l2 = l2, l2.next
        tail = tail.next
    tail.next = l1 if l1 else l2    # attach the leftover
    return dummy.next

Common problems: 21 Merge Two Sorted Lists, 203 Remove Linked List Elements, 19 Remove Nth Node From End.

Pattern 2 — Fast & slow pointers (Floyd's tortoise and hare)

Two pointers moving at different speeds turn "walk the list twice" into "walk it once", and detect cycles without extra memory:

def has_cycle(head):                # LeetCode 141
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow is fast:
            return True
    return False

The same setup finds the middle (stop when fast hits the end; slow is there), and — the elegant part — the cycle entry point: after they meet, move one pointer to the head and advance both one step at a time; they meet at the cycle's start (142). Common problems: 876 Middle, 141 Cycle, 234 Palindrome (find middle, reverse second half, compare).

Pattern 3 — In-place reversal (pointer surgery)

Reversing a list is three variables and one loop — and it's the building block for a surprising number of problems:

def reverse_list(head):             # LeetCode 206
    prev = None
    curr = head
    while curr:
        nxt = curr.next             # 1. save the rest
        curr.next = prev            # 2. flip this node's pointer
        prev = curr                 # 3. step both pointers forward
        curr = nxt
    return prev                     # prev is the new head

Every node's next is rewritten exactly once: O(n) time, O(1) space. Variants: reverse a subrange (92), reverse in groups of k (25), reorder by alternating front and back (143 — find middle, reverse second half, merge).

Pattern 4 — Doubly linked list + hash map: LRU Cache

146 LRU Cache is the flagship design problem. The requirements: get and put in O(1). Neither structure alone suffices — a hash map can't order by recency, and a list can't find keys. Together they can:

  • Hash map: key → node, for O(1) lookup.
  • Doubly linked list: nodes in recency order, most-recent at the front. Doubly is essential: you must unlink a node you reach through the map, i.e., without walking to it.
class Node:
    def __init__(self, key=0, val=0):
        self.key, self.val = key, val
        self.prev = self.next = None

class LRUCache:
    def __init__(self, capacity: int):
        self.cap = capacity
        self.map = {}                       # key -> Node
        self.head = Node()                  # sentinel: most recent side
        self.tail = Node()                  # sentinel: least recent side
        self.head.next = self.tail
        self.tail.prev = self.head

    def _remove(self, node):
        node.prev.next = node.next
        node.next.prev = node.prev

    def _add_front(self, node):             # insert right after head
        node.next = self.head.next
        node.prev = self.head
        self.head.next.prev = node
        self.head.next = node

    def get(self, key: int) -> int:
        if key not in self.map:
            return -1
        node = self.map[key]
        self._remove(node)                  # mark as most recently used
        self._add_front(node)
        return node.val

    def put(self, key: int, value: int) -> None:
        if key in self.map:
            self._remove(self.map[key])
        node = Node(key, value)
        self.map[key] = node
        self._add_front(node)
        if len(self.map) > self.cap:
            lru = self.tail.prev            # evict the least recently used
            self._remove(lru)
            del self.map[lru.key]
Why the two sentinels matter: with head and tail dummies, _remove and _add_front never need a null check — even when evicting the very last real node. This is the same sentinel trick from Pattern 1, now load-bearing.

Interview follow-ups to expect: why not a singly linked list (couldn't unlink without the predecessor), why not an array (O(n) reorder), what breaks with equal priorities (nothing — that's LFU's job, 460), and thread-safety (wrap ops in a lock — good to mention).

7. Interview checklist

  1. Empty list: Does head is None work? Does head.next explode?
  2. Head changes: Can the operation remove or replace the head? Use a dummy node.
  3. Single node: Every loop with fast.next.next needs fast and fast.next first.
  4. Return value: The original head is often stale after surgery — return the new head (prev or dummy.next).
  5. Reference vs. copy: Assigning node.next mutates the list; saved nxt pointers exist because reassignment destroys the old link.
  6. Cycle safety: Am I walking a list that might be cyclic without Floyd's?
  7. Complexity: O(n) time, O(1) space is the bar — recursion costs O(n) stack, which the interviewer may reject.
  8. Doubly links: For every prev update, is there a matching next update?

8. First practice problem — LeetCode 206

Reverse Linked List

Given the head of a singly linked list, reverse the list and return the new head. Do it iteratively with O(1) space.

Walk the list once, flipping each node's next to point backwards. The trap: flip the pointer before saving the rest of the list and you've cut yourself off — hence the three-step dance in Pattern 3.

Invariant: after processing node curr, everything from prev backwards is fully reversed, and curr still leads to the untouched remainder. When curr is None, prev is the new head.

class Solution:
    def reverseList(self, head: Optional[ListNode]) -> Optional[ListNode]:
        prev = None
        curr = head
        while curr:
            nxt = curr.next
            curr.next = prev
            prev = curr
            curr = nxt
        return prev

Time: O(n) — one pass, one pointer rewrite per node. Space: O(1). The recursive version is also O(n) time but O(n) stack — say that trade-off out loud before the interviewer asks.

  2. Why does the function return prev and not head?
  3. How would you reverse only the last k nodes of the list, reusing this code?
