A practical, NeetCode-inspired study guide for SDE mid-level interviews. The stack is the smallest data structure in this series — and the source of some of the sharpest patterns, from matching parentheses to next-greater-element and histogram rectangles.

Includes embedded diagrams, Python examples, complexity analysis, a study roadmap with direct LeetCode links, and your first practice problem. This file is self-contained and works offline. Companion guides: Heaps (the priority-based cousin) · Graphs (iterative DFS uses a stack).

1. What is a stack?

A stack is a collection where you only ever touch one end. Push adds to the top, pop removes from the top — Last-In, First-Out (LIFO). Think of a stack of plates: you put one on top, and the next one you take is the one you just put there.

  • LIFO: the last element pushed is the first popped.
  • Core ops: push, pop, peek (look at the top without removing), is_empty — all O(1).
  • The mental model: a stack holds "everything that is still unresolved". When a new item arrives, it either resolves the top item, or it becomes a new unresolved item itself. This framing is what makes the patterns below click.
  • It's already everywhere: your function-call call stack is a stack — recursion is just letting the language push and pop frames for you. Any recursive algorithm can be rewritten with an explicit stack (iterative DFS, Graphs guide).

2. Representing a stack in Python

A plain Python list is the idiomatic stack — append is push, pop() is pop:

stack = []
stack.append(5)          # push — O(1) amortized
stack.append(12)
stack.append(30)

top = stack[-1]          # peek — O(1)
popped = stack.pop()     # pop, returns 30 — O(1)
is_empty = len(stack) == 0
Performance traps: list.pop(0) and list.insert(0, x) are O(n) — they use the list as a queue, badly. If you need to add/remove at both ends, that's a collections.deque (popleft/appendleft are O(1)). See the BFS template in the Graphs guide. Python's recursion limit (~1000 frames) is the other reason to convert deep recursion to an explicit stack.

Stacks of pairs are common — e.g. index + value for monotonic stacks:

stack.append((i, nums[i]))
i, val = stack.pop()

3. Stack vs. queue vs. heap

Stack — LIFO

Most recent first. For matching, nesting, backtracking, "the unresolved thing I saw last".

Useful for: parentheses, parsing, DFS, undo, monotonic scans.

Queue — FIFO

Oldest first. For processing in arrival order, level by level.

Useful for: BFS, task scheduling. See the Graphs guide.

Heap — priority

Most extreme first, not most recent. When "next up" is decided by priority rather than arrival order.

Useful for: top-k, Dijkstra. See the Heaps guide.

The decision is one question: what determines who goes next? Last in → stack. First in → queue. Highest priority → heap.

5. Four core interview patterns

Pattern 1 — Matching and parsing

The classic: brackets. Every closer must match the most recent unmatched opener — "most recent unresolved" is literally the top of a stack:

def is_valid(s: str) -> bool:          # LeetCode 20
    pairs = {')': '(', ']': '[', '}': '{'}
    stack = []
    for ch in s:
        if ch in '([{':
            stack.append(ch)
        else:
            if not stack or stack.pop() != pairs[ch]:
                return False
    return not stack                   # every opener must have been matched

The same skeleton parses file paths (71: push components, pop on ..), decodes nested strings (394: stacks for counts and partial strings), and evaluates postfix expressions (150: push operands, pop two on each operator — order of the two pops matters!).

Pattern 2 — The monotonic stack

The highest-leverage pattern in this guide. A monotonic stack keeps its contents in sorted order by popping everything the new element makes obsolete. It answers, for each element, "what is the nearest element to my left/right that is greater/smaller than me?" — in O(n) total, not O(n²).

739 Daily Temperatures is the cleanest example — for each day, how many days until a warmer one?

def daily_temperatures(temps):          # answer[i] = days until warmer
    answer = [0] * len(temps)
    stack = []                           # indices of days awaiting a warmer day;
                                         # temperatures on the stack are decreasing
    for i, t in enumerate(temps):
        while stack and temps[stack[-1]] < t:
            j = stack.pop()              # day j finally found its warmer day: i
            answer[j] = i - j
        stack.append(i)
    return answer
The three rules of monotonic stacks: (1) Next greater → maintain a decreasing stack (pop when the incoming element is greater). (2) Store indices, not values — you usually need distances, and you can always look the value up. (3) The while loop's total work is bounded: each index enters and leaves the stack at most once, so n pushes + n pops = O(n). Saying this aloud is how you justify the complexity.

Escalations: circular arrays (503 — iterate twice or 2n with modulo), streams (901), and the hard classics 84 Largest Rectangle in Histogram and 42 Trapping Rain Water — where the stack holds candidate boundaries and each pop computes an area.

Pattern 3 — A stack with auxiliary state

Design problems ask for the stack plus a constant-time extra guarantee. 155 Min Stack: push, pop, top, and getMin — all O(1). The trick: store the running minimum alongside each value, so it pops together with the value that produced it:

class MinStack:
    def __init__(self):
        self.stack = []                  # each entry: (value, min_so_far)

    def push(self, val: int) -> None:
        current_min = self.getMin()
        self.stack.append((val, min(val, current_min)))

    def pop(self) -> None:
        self.stack.pop()

    def top(self) -> int:
        return self.stack[-1][0]

    def getMin(self) -> int:
        return self.stack[-1][1] if self.stack else float('inf')

The general lesson: when one O(1) query can't be answered from the top value alone, carry a second piece of state per stack entry. The same idea powers max-stack variants and undo systems.

Pattern 4 — Stack as an explicit call stack

Two situations force this: recursion depth beyond Python's limit, and interleaved control flow (two nested iterations, like 394 or iterator problems). The recipe: replace each recursive call with pushing a "work item", and each return with a pop. Iterative tree/graph DFS from the Graphs guide is the canonical example — swap the BFS deque.popleft() for a stack pop() and you get depth-first behavior.

7. Interview checklist

  1. Order: LIFO or FIFO? If processing order is "most recent unresolved", it's a stack.
  2. Contents: Values, indices, or both? Default to indices for monotonic stacks.
  3. Direction: Next greater needs a decreasing stack; next smaller needs an increasing one. Write the while condition, then sanity-check it against a 2–3 element example.
  4. Empty-stack guard: Every stack[-1] and stack.pop() needs a while stack and … or if not stack check.
  5. Leftover state: What happens to items still on the stack at the end? (Unmatched brackets, indices whose warmer day never came → answer 0.)
  6. Complexity: Nested while inside for is still O(n) if each element pushes/pops once — say why.
  7. Recursion limit: Is the input large enough that recursive solutions hit Python's ~1000 frames?
  8. Edge cases: Empty input, single element, all-equal elements, strictly monotonic input, sorted input.

8. First practice problem — LeetCode 20

Valid Parentheses

Given a string of ()[]{} characters, return True if every bracket is closed by the correct type, in the correct order, and nothing is left unmatched.

The key realization: the correct bracket to close is always the most recently opened and not yet closed one — which is exactly the top of a stack.

Three failure modes to cover: (1) closer arrives with an empty stack — if not stack; (2) top opener doesn't match — the pairs check; (3) openers left over at the end — return not stack. Missing any one passes most tests and fails the interview.

class Solution:
    def isValid(self, s: str) -> bool:
        pairs = {')': '(', ']': '[', '}': '{'}
        stack = []
        for ch in s:
            if ch in '([{':
                stack.append(ch)
            elif not stack or stack.pop() != pairs[ch]:
                return False
        return not stack

Time: O(n) — one pass, each character pushed or popped at most once. Space: O(n) worst case (all openers, like "(((((").

Follow-up the interviewer will ask: how would you extend this to full expression parsing with operator precedence (227)? The answer preview: one stack for operands and immediate evaluation of *//, deferring +/− as signed pushes — same "most recent unresolved" logic, one level deeper.

Practice prompts

  1. Why must the closer match the top of the stack specifically, and not any element in it?
  2. What does the final return not stack catch that the loop alone doesn't?
  3. How would you adapt the code to also validate that brackets aren't crossing, like "([)]" — does your current code already handle it?

Try writing the solution from memory, then explain the three failure modes and the complexity aloud as you would in an interview.
