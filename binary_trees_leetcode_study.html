1. What is a binary tree?

A binary tree is a hierarchical data structure in which each node has at most two children: a left child and a right child. Each node stores a value and references to its children.

  • Root: the topmost node, here 1.
  • Parent / child: a direct connection from a node to one below it.
  • Leaf: a node with no children.
  • Subtree: a node and all its descendants.
  • Depth: number of edges from the root to a node; root depth is 0.
  • Height: number of edges on the longest path from a node to a leaf. A leaf has height 0 under this convention.

Some definitions count height in nodes rather than edges. Either is fine if consistent. LeetCode's “maximum depth” is usually described as the number of nodes on the longest root-to-leaf path.

2. Representing a tree in Python

LeetCode generally gives you a TreeNode class and passes the root to your function.

class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

Build a tree manually:

root = TreeNode(1)
root.left = TreeNode(2)
root.right = TreeNode(3)
root.left.left = TreeNode(4)
root.left.right = TreeNode(5)
root.right.right = TreeNode(6)

Access nodes through references:

root.left.val        # 2
root.right.val       # 3
root.left.right.val  # 5
root.left.left.left  # None

LeetCode may display the tree as [1, 2, 3, 4, 5, null, 6]. This is a serialization format, not necessarily the representation you manipulate in your solution. Your function usually receives the root node directly.

3. Binary tree vs. BST vs. heap

Binary tree

No value-ordering rule. Each node has at most two children.

Useful for: hierarchies, paths, recursion, subtree DP, ancestor problems.

Binary Search Tree (BST)

Values in the left subtree are smaller and values in the right subtree are larger, assuming the conventional no-duplicates rule.

Useful for: ordered search, min/max, predecessor/successor, kth-smallest, LCA in a BST.

Binary heap

A complete binary tree with parent-child ordering. In a min-heap, each parent is no greater than its children.

Useful for: priority queues, scheduling, top-k problems, graph algorithms.

A BST can search in O(log n) time when balanced, but may degrade to O(n) when skewed. A heap gives O(1) access to its minimum but typically needs O(n) to search for an arbitrary value. Python's heapq provides a min-heap.

4. When should you use a tree?

Choose a tree when the data is naturally hierarchical, or when a problem can be broken into smaller left and right subproblems. A tree is not automatically faster than an array or hash map.

StructureStrengthTypical weakness
ArrayO(1) indexed accessMiddle insertions may shift elements
Hash mapO(1) average key lookupDoes not naturally model hierarchy
Linked listInsert/delete efficiently when node is knownO(n) positional access
Binary treeHierarchy, recursive decomposition, pathsArbitrary search can be O(n)
Balanced BSTOrdered operations in O(log n)Needs balancing guarantees
HeapFast access to highest-priority itemNo efficient arbitrary-value search

5. Recursion: the foundation

Consider counting the nodes in a tree. The count for a node is one (the node itself), plus the count of its left subtree, plus the count of its right subtree.

Recursive definition
count(root) = 1 + count(root.left) + count(root.right)
count(None) = 0 — this is the base case.
class Solution:
    def countNodes(self, root: Optional[TreeNode]) -> int:
        if root is None:
            return 0

        left_count = self.countNodes(root.left)
        right_count = self.countNodes(root.right)
        return 1 + left_count + right_count

Time: O(n), because every node is visited once. Auxiliary space: O(h) for the recursion stack, where h is tree height — O(log n) for a balanced tree and O(n) for a skewed tree.

The recursive function only needs the root of the subtree it is processing. This makes it reusable at every level.

6. Four core interview patterns

Pattern 1 — DFS (Depth-First Search)

DFS explores a branch before moving to another. The three classic orders differ in when the current node is processed:

Preorder

Root → Left → Right

[1, 2, 4, 5, 3]

Inorder

Left → Root → Right

[4, 2, 5, 1, 3]

Postorder

Left → Right → Root

[4, 5, 2, 3, 1]

Common problems: Maximum Depth (104), Diameter (543), Balanced Tree (110), Invert Tree (226), Path Sum (112), LCA (236), and Maximum Path Sum (124).

Key question: What information should the recursive function return to its parent? Height, validity, or best downward path are common answers.

Pattern 2 — BFS (Breadth-First Search)

BFS explores level by level. If a prompt mentions levels, the nearest qualifying node, or level-by-level output, consider BFS first.

from collections import deque

def levelOrder(root):
    if root is None:
        return []

    result = []
    queue = deque([root])

    while queue:
        level = []
        for _ in range(len(queue)):
            node = queue.popleft()
            level.append(node.val)

            if node.left:
                queue.append(node.left)
            if node.right:
                queue.append(node.right)

        result.append(level)

    return result

Time: O(n). Space: O(n) worst case for the queue and result. Common problems: 102 Level Order Traversal, 199 Right Side View, 103 Zigzag Traversal, and minimum depth.

Pattern 3 — BST properties

An inorder traversal of a valid BST visits values in sorted order. This can unlock kth-smallest, validation, and successor problems. For validation, remember that every node must respect the constraints of its entire subtree — checking only its immediate children is insufficient.

Pattern 4 — Tree DP and global state

Some problems need two kinds of information: a value returned upward to the parent, and a best answer tracked anywhere in the tree.

For the diameter, a candidate path through a node combines the heights of its left and right subtrees. If heights count edges, the candidate is left_height + right_height + 2. If heights count nodes, it is left_height + right_height when empty subtrees have height zero.

Tree DP insight: the value returned to the parent may be different from the global answer being optimized. Maximum path sum (124) is a classic example.

8. Interview checklist

  1. Input: Is the root allowed to be None?
  2. Return type: Number, boolean, node, or list?
  3. Decomposition: Can the problem be solved from left and right subtrees?
  4. Base case: What should an empty subtree return for this particular problem?
  5. Subtree information: What must each recursive call return?
  6. Global state: Do I need to track a best answer across all nodes?
  7. Complexity: How many visits per node? How deep can recursion or the queue grow?
  8. Edge cases: Empty, single-node, skewed trees, missing children, negative values, duplicates.

class Solution:
    def maxDepth(self, root: Optional[TreeNode]) -> int:
        if root is None:
            return 0

        left_depth = self.maxDepth(root.left)
        right_depth = self.maxDepth(root.right)

        return 1 + max(left_depth, right_depth)

Time: O(n), every node is visited once. Auxiliary space: O(h) recursion stack, where h is the tree height.

  2. How do you calculate the left and right subtree depths?
